# P2: deterministic, evidence-preserving code intelligence

P2 adds an index over source evidence, not a replacement for source. No LLM, embeddings, ranking, context budgeting, MCP, editor integration or cloud sync is included.

## Architecture and files

- `packages/indexer/src/scan.ts`: deterministic scanner, ignores, language detection, containment and safe reads.
- `packages/indexer/src/parser.ts`: pinned Tree-sitter WASM registry; TS/TSX/JS/JSX/Python extraction into plain validated IR.
- `packages/indexer/src/index.ts`: run lifecycle, Git metadata, incremental reuse, atomic publication and explicit failures.
- `packages/codegraph/src/domain.ts`: IR, spans, strict event schemas, node/edge contracts, identities and adapter interfaces.
- `packages/codegraph/src/resolve.ts`: deterministic local import and conservative lexical/receiver resolution.
- `packages/codegraph/src/replay.ts`: pure run/file-version replay; only completed runs publish current observations.
- `packages/codegraph/src/index.ts`: transactional projection rebuild/cache validation and query APIs.
- `packages/storage/src/blobs.ts`: immutable content-addressed byte storage and integrity checks.
- `packages/storage/migrations/003_code_intelligence.sql`: source blob storage, derived code tables and code event allowlist.
- `fixtures/repos/typescript-basic`, `fixtures/repos/python-basic`, `fixtures/changes`: explicit structural/version fixtures.
- Tests live under indexer, codegraph and CLI. Existing P0/P1 suites remain active.

The IR and parser interface live in codegraph so graph reconstruction can request an adapter without depending on Tree-sitter. Indexer implements the adapter and produces the IR. Storage owns all DDL and transactions. CLI coordinates services only.

## Canonical schema and immutable evidence

Migration 003 adds these event types to the existing immutable envelope:

| Event | Payload |
| --- | --- |
| `code.index.started` | UUID `index_run_id`, `root_path`, UTC `started_at` |
| `code.file.observed` | Run ID, normalized `path`, `language`, `content_hash`, `byte_length`, `parser_id`, `parser_version`, UTC `observed_at`, optional Git commit/branch/dirty metadata |
| `code.file.deleted` | Run ID, path, `previous_content_hash`, UTC `observed_at` |
| `code.index.completed` / `code.index.failed` | Run ID, completion time, seen/changed/unchanged/deleted counts, parse-error count, explicit path/error list, metrics |

Every envelope retains P0's deterministic ID, project/session IDs, per-project sequence, event type, payload, timestamp and content hash. New event payloads fail closed on unknown fields, invalid paths/types, missing blobs, inconsistent counters, overlapping runs or invalid lifecycle transitions. Events never contain ASTs or graph edges.

`source_blobs(content_hash TEXT PRIMARY KEY, byte_length INTEGER, content BLOB, created_at TEXT)` stores the exact bytes passed to the parser. SHA-256 identifies content. UTF-8 BOM, Unicode, CRLF and trailing bytes are not normalized. UTF-8 decoding is strict: invalid encoding fails the run but its attempted source bytes are still preserved.

Insertion deduplicates by hash; reads recheck byte length and SHA-256. SQLite triggers reject UPDATE, DELETE and replacement inserts. Blobs have no automatic retention or garbage collection. Identical bytes across files/projects/versions occupy one row. Blob writes and corresponding observation events share a transaction.

The schema-only event CHECK extension follows the P1 migration approach: preserve the event table/root page/rows/triggers, update its schema allowlist within the migration transaction, bump the SQLite schema version, reset writable-schema mode and run integrity checks. Migrations 001/002 are unchanged. Migration tests verify P0/P1 rows, rowids, triggers, memory projections and checksums survive, including rollback on failure.

Derived tables are `code_files`, `code_symbols`, `code_edges`, `code_imports`, `code_index_runs` and `code_projection_state`. All are project-scoped and disposable. The file projection caches validated extraction; the projection state records a digest and event cursor. Source events and blobs have no dependency on these caches.

## Parsing, spans and identities

Supported extensions: `.ts`, `.mts`, `.cts`, `.tsx`, `.js`, `.mjs`, `.cjs`, `.jsx`, `.py`.

The pinned `@vscode/tree-sitter-wasm@0.3.1` bundle supplies runtime and language grammars. Parser ID names the language adapter; parser version combines extractor revision, runtime WASM hash and grammar WASM hash. Replay refuses unavailable recorded versions rather than silently changing semantics. Any future extraction/resolution semantic change must bump the extractor revision and retain old adapters when historical reparse is required. See the [official bundle repository](https://github.com/microsoft/vscode-tree-sitter-wasm).

Tree-sitter's JavaScript offsets are converted from UTF-16 string offsets to original UTF-8 byte offsets. Spans contain the source hash, start/end bytes, and start/end line/column. Byte ranges are end-exclusive; lines are 1-based; columns are 0-based byte columns. Validation recomputes coordinates against preserved bytes, rejects out-of-range evidence, invalid roots/parents/scopes, cycles and duplicate identities. No Tree-sitter objects enter persistent models.

Nodes: file, module, class, interface, type, function, method, variable, constant, parameter, import and export. Exported declarations carry an export flag and EXPORTS edges; export clauses also yield export nodes. Unsupported syntax is not classified as speculative services/controllers/repositories.

Logical IDs hash a domain tag, project ID, canonical `/` path, language, kind, qualified name and discriminator. Ordinary body edits and inserted lines do not change a unique named symbol's logical ID. Repeated qualified names use normalized declaration-signature hashes and an occurrence ordinal for identical signatures. Overloads therefore have distinct identities and are not guessed as definitive call targets. Renames/moves change identity; anonymous and indistinguishable repeated declarations have weaker identity stability. Version IDs additionally hash exact source span/hash and parser version.

## Resolution and evidence

Edges: CONTAINS, DEFINES, IMPORTS, EXPORTS, CALLS, REFERENCES, EXTENDS and IMPLEMENTS. Every edge records source/target IDs, original byte span, observation event ID, resolution type and EXTRACTED or RESOLVED classification. No INFERRED edges are produced.

TS/JS local imports resolve relative paths, exact files, common extensions and `index` candidates. Python resolves straightforward repository-local `.py` modules, package `__init__.py`, and relative modules. Resolution requires one candidate. External packages, missing files and ambiguous extension/index matches remain unresolved.

Calls resolve unique lexical functions, directly imported named symbols, simple namespace imports and directly declared methods on an unambiguous `this`/`self`/`cls` receiver. Parameters, duplicate bindings, reassignment and dynamic receivers prevent definitive calls. Bare method names are not treated as implicit receiver calls. Nested imports are not promoted to module scope. Block/comprehension/lambda/global/nonlocal binding semantics not modeled in P2 conservatively disable resolution in the affected declaration scope and retain diagnostics.

Unresolved relationships remain in cached IR and diagnostics and are reproducible from blobs. This favors precision over graph density. There is no type checker, runtime execution, package-manager emulation, alias configuration, general re-export/default-import resolution, CommonJS `require` resolution, virtual dispatch or monkey-patching analysis. Static structural evidence does not promise runtime call behavior.

## Scanning and incremental indexing

Entries are sorted deterministically. Canonical paths use `/`; absolute paths and any `..` segment are rejected. Scanning ignores `.git`, `.graphit`, `node_modules`, `dist`, `build`, `coverage`, `.next`, `out`, `vendor`, Python caches and virtual environments. An API-level additional ignore-name list is supported; `.gitignore` parsing/config frameworks are not implemented.

Symlinks are not followed. A skipped symlink (including a cycle) is reported as an error, never hidden behind a successful status. Reads check path containment, real paths, regular-file status and size/mtime changes; `O_NOFOLLOW` is used where available. This is not an adversarial filesystem snapshot guarantee against concurrent ancestor-directory replacement. Keep the repository stable during indexing and retry if reads race with edits.

Every discovered supported file is read and hashed before parsing. Matching content hash and parser identity reuse persisted extraction with zero parser calls and zero duplicate blobs/observations. New/changed files alone are parsed. Deleted files receive tombstone events only after a complete scan. A rename is an observation at the new path plus a deletion at the old path; bytes remain deduplicated. Cross-file resolution and derived graph publication are recomputed globally even when parsing is incremental.

Git is optional. When available, observations include commit SHA, branch (null for detached HEAD), and dirty state. Working-tree content hashes, not Git metadata, identify evidence. Unchanged files keep their original observation metadata.

## Transactions, failures and rebuild

Storage retains WAL, synchronous FULL and BEGIN IMMEDIATE writes. A started event is committed before work begins. A final transaction inserts blobs, observations/deletions, completion/failure and projections. Only a completed run replaces the current graph. Parse/scan failures preserve attempted source and explicit errors while leaving the previous successful graph intact. Graph-publication failure rolls back partial projections, then attempts a failed observation batch that preserves parsed bytes. If storage itself is unavailable (disk full, corruption, permission loss), persistence cannot be promised: the command errors and the started run remains visibly unfinished where durable.

A process interrupted before the final transaction leaves a running record with null `completed_at`; it cannot claim successful indexing. `--rebuild` explicitly records failure for an unfinished run before retrying. It must not be used concurrently to cancel another live indexer; P2 has no process lease/heartbeat.

`CodeGraphService.rebuildCodeProjection(projectId)` replays immutable events to select active versions, reads/validates their blobs, reparses using recorded adapters, resolves relationships, and atomically replaces only that project's code projections. It never reads current source files and never deletes events, blobs or P1 memory. Missing/corrupt projection data is detected and rebuilt. Missing/corrupt source or an unavailable parser fails closed. No source is repaired automatically.

`graphit index --rebuild` performs this explicit reparse/recovery and then indexes the current working tree. Rebuild parser calls are separate from the run's incremental `files_parsed` count.

## Query APIs and CLI

All service queries take `projectId` first:

`getSymbol`, `findSymbolsByName`, `getFile`, `getOutgoingEdges`, `getIncomingEdges`, `getCallers`, `getCallees`, `getImports`, `getDefinitions`, `getSource`, `stats`, `getRuns`.

```sh
graphit index [path] [--json] [--rebuild]
graphit code stats [--json]
graphit code symbol <name-or-id> [--json]
graphit code callers <name-or-id> [--json]
graphit code callees <name-or-id> [--json]
graphit code imports <relative-file> [--json]
graphit code source <logical-symbol-id-or-version-id> [--json]
```

Index auto-initializes a non-Graphit directory; Git is not required. Explicit paths must identify the full project root, not a subtree. Existing projects are discovered upward. The workspace executable can be invoked with `npm exec -- graphit ...` without a global install.

Name lookup is exact name/qualified-name matching, not fuzzy search. Ambiguity returns ordered candidates instead of silently selecting one. Source uses preserved blobs: a logical ID selects current indexed evidence; a historical version ID retrieves that old version even after a working-tree edit/reindex/deletion. Historical lookup reparses successful observations and can be slow. Failure summaries return nonzero exit status. P0/P1 commands remain supported.

## Verification and baseline

```sh
npm test
npm run typecheck
npm run lint
npm exec -- graphit index .
npm exec -- graphit code stats --json
```

Tests cover fixtures, five languages, Unicode/CRLF/BOM spans, return-1 evidence after return-2 edits, historical versions, deduplication, incremental parser-call counts, deletion/rename, overloads/ambiguity, rebuild equivalence, P1 isolation, raw-SQL blob immutability/corruption, malformed extraction, missing blobs, rollback, interrupted/failed runs, symlink cycles, traversal, Windows paths, unavailable adapters, migration upgrades and CLI processes.

Run metrics include scanned/parsed/reused files, bytes read, symbols extracted from changed files, total resolved/current graph edges and duration in milliseconds. Duration is measured through extraction/resolution before the final completion append; it excludes the last commit overhead. Empty/unchanged runs still read/hash source and rewrite disposable graph projections. Baselines are machine/run-specific, not performance guarantees.

Verified on 2026-09-26 with Node 22.17 on Windows: **146 tests passed across 9 files**; `npm run typecheck`, `npm run lint` and `git diff --check` passed. The real workspace CLI indexed this repository successfully, and an unchanged rerun made zero parser calls (also independently asserted by the test registry wrapper).

Stats reported 33 TypeScript, 4 JavaScript, 3 Python, 1 TSX and 1 JSX files; 4,776 unresolved references; completed status; zero parse errors. The high unresolved count is intentional: unsupported binding scopes and external/dynamic references are retained, not guessed into edges. Local smoke-test data lives in ignored `.graphit/graphit.db`.

Large repositories/history are not yet optimized: scanning, parsing, evidence validation, replay and graph assembly are synchronous and memory-resident; several operations are quadratic. Source blobs grow indefinitely. Rebuild depends on retaining the exact parser implementation. Hashes detect accidental mismatches, not malicious database replacement. Use a local WAL-compatible filesystem and back up events plus source blobs together.
