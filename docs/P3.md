# P3: evidence retrieval and provider-neutral context compilation

P3 adds disposable search/context over immutable P0 events, P1 memory and P2 source evidence. It makes no LLM calls and adds no embeddings, vector database, MCP, VS Code, cloud sync, agent execution or automatic memory extraction.

## Packages and data flow

- `@graphit/retrieval`: normalized query contract, independent candidate channels, RRF, bounded Personalized PageRank, reverse impact traversal, explicit memory/code links, redundancy scoring and benchmark helpers.
- `@graphit/context`: evidence units, immutable byte-window selection, provider-neutral token estimator, MMR-guided packing, canonical JSON and human-readable rendering.
- `@graphit/storage`: migration 004 and narrow project-scoped search operations inside existing transactions. Retrieval owns ranking, not the CLI.

New implementation files:

- `packages/retrieval/src/{domain,index,ranking,metrics}.ts`
- `packages/context/src/{evidence,index}.ts`
- `packages/storage/src/search.ts`
- `packages/storage/migrations/004_retrieval.sql`
- Tests under retrieval/context and expanded CLI tests.
- `fixtures/repos/auth-retrieval/`
- `examples/context-demo.mjs`, `examples/context-self-benchmark.mjs`

Build order extends P2 with retrieval → context → CLI. No P0/P1/P2 event schema, source blob format or existing migration is changed.

## Migration and FTS

Migration 004 adds:

| Derived object | Indexed fields |
| --- | --- |
| `retrieval_memory_fts` | content, entity_type, status |
| `retrieval_code_fts` | name, qualified_name, path, signature |
| `retrieval_projection_state` | project_id, document_hash |

Both FTS5 tables also carry unindexed project ID and entity/symbol ID. SQLite creates its own FTS shadow tables. Full source blobs are never copied into FTS. CamelCase, underscore and Unicode lexical terms are appended to search documents only; canonical memory/source remains unchanged.

Before searching, validated memory replay and the code graph supply search documents. The service compares their digest and stored FTS content against the derived index, rebuilding stale/missing rows transactionally. `rebuildSearchProjection(projectId)` forces this process. Tests delete all retrieval rows and compare rebuilt rankings while asserting events, blobs, memory and code rows are unchanged. Migration tests cover schema/root-page/ledger preservation and FTS DDL rollback.

FTS terms are quoted literal tokens, joined with OR, and passed as bound SQL parameters. Arbitrary user FTS operators are not executed. Lower SQLite BM25 scores rank first, then stable IDs. See [SQLite's FTS5 documentation](https://www.sqlite.org/fts5.html) for MATCH and BM25 behavior.

Search is project-filtered. In the uncommon multi-project-in-one-database API case, FTS5 corpus statistics are shared; other projects' text never appears in results, but adding their documents can affect BM25 scores. The CLI uses one project per database.

## Query contract and independent channels

`RetrievalQuery` accepts text, projectId, optional tokenBudget, activeSessionId, seedSymbolIds, seedMemoryIds, currentFiles, mode and includeHistorical. Strict validation rejects unknown fields, empty text, invalid IDs/budgets, unsafe paths and missing seeds.

Normalization uses NFKC, trimmed/collapsed whitespace, camelCase/underscore splitting, lowercase Unicode lexical tokens and a fixed stop-word set. Project-name terms are removed from broad lexical queries. Auto mode uses explicit word rules for continue/impact, never a model. Exact name/ID/path matching remains independent of lexical normalization.

Candidate channels are:

1. Explicit memory/symbol/file seeds.
2. Exact symbol/name/qualified-name/ID matches, retaining all ambiguous matches.
3. Exact/substring file-path matches.
4. Symbol-name lexical overlap (declarations, not generic local-variable mentions).
5. Code FTS/BM25.
6. Memory FTS/BM25.
7. Current project state: goals, tasks, constraints, blockers, decisions, results and questions.
8. Continue-mode state/session priority.
9. Personalized PageRank.
10. Reverse-impact reachability.

Whole-query exact variable lookup still works. Within natural-language sentences, identifier-word exact matching is restricted to function/method/class/interface/type declarations; words such as “source” and “current” do not turn every local variable into mandatory context.

Canonical RRF is `sum(1 / (k + rank))`, using 1-based independent ranks and configurable `k=60`. Raw BM25/PPR scores are diagnostics, not normalized into a fabricated common scale. Explicit and exact-match priority tiers sit above RRF; impact reachability has its own priority tier. Within a tier, RRF score then stable ID determines order. Final context relevance is the fused score divided by the largest fused score, with explicit/exact matches at 1.

`retrieve()` exposes each candidate's channel/rank/raw-score records, RRF score, PPR score, final relevance, temporal status and symbol/memory evidence. Ambiguous exact matches are listed separately.

## Current graph, PPR and impact

Normal memory eligibility is active/in-progress with an open validity interval; results with open validity remain eligible. Completed tasks, cancelled or superseded memory do not enter the current expansion graph. `includeHistorical: true` and explicit memory seeds expose historical entries marked non-current. Explicit historical symbol-version seeds retrieve preserved P2 evidence. Old graph snapshots are not a P3 API.

Current code edges and valid memory relationships are combined only where explicit links exist. Supersession relations are not used to pull obsolete decisions into normal PPR. Seeds include explicit/exact/path matches, up to eight results per BM25 channel and up to eight active goals/tasks.

Defaults:

| Setting | Value |
| --- | ---: |
| RRF k | 60 |
| PPR damping | 0.85 |
| Maximum graph hops | 3 |
| Maximum expanded nodes / final candidates | 200 |
| Minimum PPR score for its ranking channel | 0.000001 |
| Maximum iterations | 100 |
| L1 convergence tolerance | 1e-10 |

Bounded deterministic BFS chooses the subgraph before PPR. Restart mass is uniform over retained seeds. Dangling mass returns to the same personalization distribution. Normal expansion uses both directions for neighborhood discovery; evidence keeps the original directed edge. Impact mode traverses incoming CALLS, REFERENCES, IMPORTS, DEPENDS_ON, TARGETS, BLOCKS, VERIFIED_BY, DEFINES and CONTAINS. It answers structural reachability, not a prediction of breakage.

Weights are exported/configurable:

- 3: CALLS, REFERENCES, TARGETS, DEPENDS_ON, BLOCKS, VERIFIED_BY, RESOLVES.
- 2: IMPORTS, EXTENDS, IMPLEMENTS, DEFINES, CONTAINS, EXPORTS, PART_OF, PRODUCED.
- 1: RELATED_TO and otherwise unspecified relationships.

These are initial priorities, not learned confidence. Caps, weights, damping and thresholds are configurable through `RetrievalService`.

## Explicit memory-to-code links

`linkMemoryToSymbol(projectId, memoryId, symbolId)`, exposed by the CLI, reuses P1 events:

1. Create a deterministic artifact containing the symbol label/path and metadata binding its logical/version IDs to an observation event and blob hash.
2. Link the memory entity to that artifact with P1 RELATED_TO and explicit TARGETS metadata.
3. Derive an artifact → current symbol TARGETS edge only when the recorded observation/path/hash provenance validates.

Both appends share one transaction; retries are idempotent. Invalid/cross-project symbols or non-current memory fail closed. The code snapshot's project sequence is checked under the write lock. No new canonical link table or duplicate event family is introduced. A changed symbol with the same logical ID stays linkable; a deleted/renamed symbol no longer supplies a current graph endpoint. Historical link events remain intact.

## Evidence and provenance

An EvidenceUnit carries ID, kind, section, relevance, content, estimated cost, event IDs, provenance classification, current/historical status, optional blob/span/symbol/memory/path fields and metadata.

Memory content is copied exactly from replayed memory; superseded content is never relabeled current. Test/command-result kinds require corresponding source-event types. Source snippets come exclusively from validated immutable blobs, never filesystem rereads.

Source evidence includes symbol/version ID, path, hash, exact end-exclusive byte range and 1-based line coordinates. For a symbol over the default 1,800-byte window target, the compiler chooses contiguous original lines around lexical matches. It does not rewrite code or insert ellipses. An indivisible long line can exceed the window target and be excluded by the budget; `partial` is explicit.

Graph-path evidence has a structured `graph_path` object with labeled/path-qualified endpoint nodes and original directed edges. Each edge retains event IDs and, for code, its source span. Packet graph/state sections reference evidence IDs to avoid duplicating content. Endpoint orientation remains within the path even if their full source snippets do not fit.

Every evidence event ID is checked against the project's immutable stream. Missing/corrupt source fails visibly. Canonical root information is neither deleted nor summarized.

## MMR, estimation and packing

The exported TokenEstimator interface is `{ id, version, estimate(text): number }`. Default `graphit:utf8-bytes-per-four@1` estimates `ceil(UTF8 byte length / 4)`. This is deterministic and provider-neutral, not a guaranteed OpenAI/Anthropic/Gemini token count. Custom estimators must identify themselves and return finite nonnegative integer costs.

MMR uses `lambda=0.7` relevance and `0.3` redundancy penalty. Similarity is the maximum of exact entity identity, source-span containment/overlap, symbol-set overlap, lexical Jaccard, provenance overlap and a small same-file penalty. No embedding is computed. MMR ordering is calculated before packing; near-identical optional evidence is omitted.

Packing uses fused relevance/diversity utility divided by square-root token cost, with deterministic criticality tiers. Explicit requirements/seeds, current goals/tasks, decisions/constraints/blockers and leading source evidence take priority. Continue mode also reserves a relevant result. Configurable `minimumReservations` specifies minimum evidence-unit counts by section, with one graph and one result unit by default when available. Reservations are not fixed budget percentages.

The compiler serializes prospective whole packets and estimates their full JSON cost, including IDs, labels, provenance, diagnostics and the budget envelope. A monotonic fixed-point calculation may conservatively overestimate by a few tokens around numeric field boundaries. It never blindly truncates output.

If mandatory evidence cannot fit, `budget_insufficient=true` and missing IDs are explicit. An extremely tiny budget cannot fit even the empty JSON envelope; the compiler returns the honest minimal packet with insufficiency, rather than invalid/truncated JSON. It does not paraphrase an oversized decision to force a fit.

Ordering is deterministic for the same database, query and configuration. Latency and index-repair diagnostics are excluded from the canonical packet. `compileWithMetrics()` separately returns full channel rankings, per-unit inclusion/exclusion reasons, redundancy penalties, costs and timing; this verbose development report is not itself budgeted. `compile()` returns just the compact packet.

## CLI and APIs

```sh
graphit retrieve "<query>" [--json] [--limit <n>] [--mode auto|code|memory|impact|continue]
graphit context "<query>" [--tokens <n>] [--json] [--mode <mode>] [--file <path>] [--symbol <id>]
graphit memory link <memory-id> --symbol <symbol-id> [--json]
```

Context defaults to 2,000 estimated tokens; repeat --file/--symbol for multiple seeds. Historical memory is available through the API. Context JSON is canonical compact JSON. Plain text is an oriented view; its layout is not the canonical budget target. CLI returns 1 for errors and 2 when context is budget-insufficient. No-result output and missing current task/goal state are explicit.

On Windows, use `.\node_modules\.bin\graphit.cmd` or `node packages/cli/dist/index.js` if the PowerShell npm shim consumes --tokens/--mode flags. The required smoke tests use the actual workspace executable.

Core P3 APIs:

- `RetrievalService.retrieve(query, {limit?, rebuild?})`
- `RetrievalService.rebuildSearchProjection(projectId)`
- `RetrievalService.linkMemoryToSymbol(projectId, memoryId, symbolId)`
- `ContextCompiler.compile(query, options)`
- `ContextCompiler.compileWithMetrics(query, options)`
- `serializeContext(packet)`, `renderContext(packet)`
- `reciprocalRankFusion`, `personalizedPageRank`, `mmrOrder`
- `retrievalMetrics` (Recall@K/MRR), `evidenceQuality` (required-ID recall and missing IDs)

## Limitations and next phase

- Deterministic lexical/structural retrieval is not semantic understanding. Local variables, fixtures and tests can still rank alongside production declarations. Fixture success is not a universal quality claim.
- P2's conservative unresolved relationships remain unresolved; P3 cannot recover absent edges. Impact means recorded structural reachability, not runtime failure prediction.
- No automatic memory promotion: continue mode needs recorded goals/tasks/results or explicit seeds.
- Bounded candidates and 20 materialized graph paths limit context breadth. Full raw source is still recoverable through P2 even when only a source window is selected.
- Synchronous replay, graph validation, search-document validation and MMR are suitable for the measured small repository, not million-node graphs. Retrieval currently obtains the SQLite write lock for derived-index maintenance.
- Full diagnostics live in the separate unbudgeted API report/retrieve output. Provider-specific tokenizers, multimodal context, summarization and persistence of compiled packets are absent.
- Source blobs/history remain append-only and grow indefinitely. Search/context are disposable; deleting them does not reclaim or modify canonical data.

Exact next step: review these fixture quality gates and approve a separate P4 integration/acceptance specification. No P4, MCP or VS Code work is started.
